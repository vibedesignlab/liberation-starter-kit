# Visual Direction 승인 후 디자인 토큰 적용 계약

이 계약은 사용자가 Phase 3 Visual Direction을 승인한 직후 사용한다. 승인은 제한된 디자인 토큰 패치를 활성화하며, 제품 전체를 시각적으로 변환할 권한은 주지 않는다.

## 적용 준비 조건

다음 조건을 모두 만족할 때만 토큰을 적용한다.

- Visual Direction 문서가 승인되었다.
- 승인 요청에서 승인 직후 `apply`로 표시된 행만 적용된다는 효과를 미리 알렸다.
- 모든 `apply` 행에 정확한 토큰 경로, 현재값, 승인값, 대상 파일, 활성 범위, 근거가 있다.
- 승인값, 대상, 범위, 의존성, 기존 작업과의 충돌이 미해결 상태로 남아 있지 않다.

하나라도 미해결이면 그 결정을 막는 질문만 하고 코드는 변경하지 않는다.

## 결정값 의미

- `apply`: Visual Direction 승인 직후 이 토큰을 변경한다.
- `keep`: 검토했지만 현재 값을 의도적으로 유지한다.
- `defer`: 방향은 유효하지만 미확정이거나 후속 작업 의존성이 있거나 토큰 한정 패치의 범위를 벗어난다.

구현 파일을 변경할 수 있는 것은 `apply` 행뿐이다. Visual Direction에 적힌 모든 문장이 자동으로 토큰 변경이 되는 것은 아니다.

## 허용되는 변경

- 명시된 theme 원본 파일.
- 해당 theme을 노출하는 데 필요한 최소 export 또는 registry 변경.
- 승인된 범위에서 theme을 활성화하는 데 필요한 최소 provider 또는 theme 선택 변경.
- 기준 Visual Direction 문서의 적용 상태와 결과.

## 허용되지 않는 변경

- 컴포넌트 마크업, variant, `sx` override.
- 페이지 레이아웃, 템플릿, route, navigation.
- 카피, 콘텐츠, fixture, 애플리케이션 데이터.
- 이미지, 일러스트, 아이콘 및 기타 에셋.
- 선언된 theme 대상 밖의 CSS override.
- 별도 허가 없는 패키지 설치, 폰트 다운로드, 네트워크 의존 설정.
- 광범위한 UI 변환, commit, push, deploy.

승인된 폰트를 로컬에서 바로 사용할 수 없다면 해당 행을 `defer`로 두거나 blocked로 보고한다. 이 계약 안에서 설치하거나 다운로드하지 않는다.

## 적용 절차

1. 현재 theme 구현과 dirty diff를 확인하고 다른 작업은 보존한다.
2. 완전한 `apply` 행만으로 정확한 패치를 계산한다.
3. `apply_patch`로 명시된 theme 원본을 수정한다.
4. 승인된 활성 범위에 꼭 필요한 export, registry, provider, 선택 연결만 추가한다.
5. 각 승인 토큰의 실제 소스 값을 검증한다.
6. Visual Direction 문서의 토큰 적용 결과 표와 상태를 갱신한다.
7. 범위에 맞는 정적 검사와 저장소 lint를 실행한다.
8. 적용 범위를 보고하고 멈춘다. 컴포넌트와 페이지 변환은 별도의 후속 작업으로 취급한다.

`apply` 대상이 출처를 분리하기 어려운 기존 수정과 겹치면 덮어쓰지 말고, 작업을 막는 결정 하나만 사용자에게 요청한다.
